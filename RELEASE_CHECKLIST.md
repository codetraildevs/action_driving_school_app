# Release Checklist — Action Driving School

> Use this checklist every time you prepare a new release for Google Play Console.

## 1. Prerequisites

- [ ] **Backend deployed with the `clientType` login logic** — the production backend must run the build that accepts `clientType` on `POST /api/auth/login` (admins sign in phone-only from the app; the web console still requires the real password). The archive `backend-deploy.tar.gz` contains it — see `docs/redeploy-backend-cpanel.md`. Verify with a curl login probe before rollout.
- [ ] **Keystore present** — `app/upload-keystore.jks` exists (PKCS12 format)
- [ ] **Gradle version catalog ready** — `gradle/libs.versions.toml` is the single source of truth for all dependency versions
- [ ] **`keystore.properties` present** at project root (`DRIVINGSCHOOL2/keystore.properties`) with:
  ```properties
  storeFile=upload-keystore.jks
  storePassword=<your-store-password>
  keyAlias=upload
  keyPassword=<your-key-password>
  ```
- [ ] **Upload key active** — Google Play Console upload key matches the keystore (verify fingerprints — see §4.5/§4.6 for upload-key vs app-signing-key distinction)
- [ ] **google-services.json** — present at `app/google-services.json` (not committed, use `google-services.json.example` template)
- [ ] **Clean working tree** — `git status` shows no uncommitted changes (except intentional ones)

### 4.5 Verify fingerprints match Play Console
```bash

```
- [ ] **SHA1:** `AD:14:AD:F8:8B:2B:11:C5:37:99:D7:29:09:42:D0:25:9D:25:D3:11`
- [ ] **MD5:** `8A:12:73:7F:B9:44:CE:52:58:DC:8E:5E:4F:E8:3D:65`
- [ ] **SHA256:** `0F:64:F1:F1:BD:C5:D3:65:4F:E8:4E:F7:CE:2E:F3:98:78:E8:73:E6:A6:B9:BC:18:C5:68:D9:B7:51:01:D2:32`

### 4.6 Upload key vs App signing key — they are SUPPOSED to differ

Play App Signing uses **two different keys**. Comparing them will always "mismatch" — that is not an error.

| | **Upload key** (yours, local) | **App signing key** (Google's, hosted) |
|---|---|---|
| SHA256 | `0F:64:F1:F1:BD:C5:D3:65:4F:E8:4E:F7:CE:2E:F3:98:78:E8:73:E6:A6:B9:BC:18:C5:68:D9:B7:51:01:D2:32` | `E2:0D:D2:4F:DC:7C:2D:56:BB:E1:49:94:73:91:73:FD:3E:2B:14:9E:5F:5F:E7:24:7B:4C:6F:A9:C1:1A:25:CC` |
| Owner | `CN=Nomiso` (self-signed, valid until 2053) | Generated by Google when Play App Signing was enabled |
| Stored in | `app/upload-keystore.jks` (passwords in gitignored `keystore.properties`) | Google's servers — you can never see the key, only its certificate |
| Used for | Signing the `.aab` you upload to Play Console | Signing the APKs users actually install |

**Where each fingerprint belongs:**

- **Upload key (`0F:64…`)** → verified by **Play Console → Setup → App signing → "Upload key certificate"** when you upload an `.aab`. `app/upload_certificate.pem` is Play's copy of this exact certificate.
- **App signing key (`E2:0D…`)** → register in **Firebase Console → Project settings → Your apps → SHA-256**, Google Cloud OAuth clients, App Check, and any third-party service that verifies installed-app signatures. It is what a tool reads from the installed app on a device.

**Symptoms of mixing them up:** Play uploads keep working, but App Check / API-key restrictions fail because the wrong fingerprint was registered (or vice versa).

> Note: the Sep 2026 keystore-password rotation changed only the local file and password. The upload certificate SHA256 `0F:64…` is unchanged, and the app signing key `E2:0D…` is unaffected by anything stored locally.

## 5. Package for Delivery

- [ ] Create `release/` directory in project root (if not exists)
- [ ] Copy AAB with descriptive name:
  ```bash
  cp app/build/outputs/bundle/release/app-release.aab release/ActionDrivingSchool-v{X.Y.Z}-build{N}.aab
  ```
- [ ] Optionally copy keystore, properties, and PEM certificate alongside:
  ```bash
  cp app/upload-keystore.jks release/
  cp keystore.properties release/   # ⚠️ contains passwords — keep secure
  cp app/upload_certificate.pem release/
  ```
- [ ] Verify all files in `release/`:
  ```bash
  ls -lh release/
  ```

## One-Time Setup

Create `DRIVINGSCHOOL2/keystore.properties`:

```properties
storeFile=upload-keystore.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=upload
keyPassword=YOUR_KEY_PASSWORD
```

> ⚠️ **Do not commit this file.** It is gitignored. The CI (GitHub Actions) uses env vars instead.
